# Heroku Userbot на Amvera Cloud (хостинг без терминала)

Amvera — это «app engine»: вы не получаете SSH и не вводите команды руками.
Вместо терминала есть три вещи:

| Терминал на VPS | Amvera |
|---|---|
| команда запуска в консоли | файл `amvera.yml` → `run.command` / `CMD` в Dockerfile |
| ввод API ID, телефона, кода из Telegram | страница входа с QR-кодом (этот каталог) |
| файлы в `~/.heroku` | постоянное хранилище `/data` |

Поэтому в проект добавлены три файла:

* `amvera.yml` — конфигурация приложения (Docker, порт 8080, диск `/data`);
* `deploy/amvera/Dockerfile` — образ: код в `/app`, данные в `/data`;
* `deploy/amvera/supervisor.py` — то, что заменяет консоль: поднимает
  веб-страницу входа с QR-кодом, сохраняет сессию в `/data/sessions` и
  запускает `python -m heroku --root`, перезапуская его при падении.

Схема работы:

```
Telegram (сканируете QR)
        │
        ▼
supervisor.py ──► /data/config.json   (api_id, api_hash)
        │      └─► /data/sessions/heroku-<id>.session
        │
        └──► python -m heroku --root  (сам юзербот, работает постоянно)
```

---

## Шаг 0. Что нужно

1. Аккаунт Amvera и созданное приложение (тип **«Приложение»**).
2. Тариф минимум **1 ГБ RAM / 1 vCPU** — юзербот с зависимостями меньше не
   переваривает.
3. `api_id` и `api_hash` с [my.telegram.org](https://my.telegram.org) →
   *API development tools*. Одна пара на аккаунт, не делитесь ею.

## Шаг 1. Загрузите код

Вариант «GitHub» (удобнее — обновления делаются через `git push`):

1. В Amvera: **Приложения → Создать приложение → GitHub**.
2. Подключите GitHub и выберите репозиторий с этим кодом, ветку — свою.
3. Amvera сама найдёт `amvera.yml` в корне.

Вариант «ZIP-архив»: скачайте репозиторий архивом, загрузите его в проект.
`amvera.yml` должен оказаться в корне архива.

> Важно: собирается **Dockerfile** `deploy/amvera/Dockerfile`, обычная
> Python-сборка Amvera не подойдёт — юзерботу нужны `ffmpeg`, `libmagic`,
> `git` и компилятор для модулей.

## Шаг 2. Проверьте конфигурацию

Вкладка **«Конфигурация»** проекта должна показывать:

```yaml
meta:
  environment: docker
  toolchain:
    name: docker
    version: latest

build:
  dockerfile: deploy/amvera/Dockerfile

run:
  persistenceMount: /data
  containerPort: 8080
```

Если вы меняли порт — поменяйте его и в `amvera.yml`, и в `Dockerfile`
(`APP_PORT`), иначе Amvera будет отдавать `503 Service Unavailable`.

## Шаг 3. Переменные проекта

Вкладка **«Переменные»** → добавьте:

| Переменная | Значение | Обязательно |
|---|---|---|
| `api_id` | число с my.telegram.org | да |
| `api_hash` | 32 символа с my.telegram.org | да |
| `AMVERA_LOGIN_TOKEN` | свой ключ доступа к странице входа | нет |

Имена `api_id` / `api_hash` — именно в нижнем регистре: юзербот читает их
как `os.environ["api_id"]`. Можно вместо переменных загрузить
`/data/config.json` вида `{"api_id": 123456, "api_hash": "..."}`.

`AMVERA_LOGIN_TOKEN` — пароль к странице первого входа. Если не задать,
Amvera-версия сама сгенерирует ключ и напечатает его в логах.

## Шаг 4. Соберите и запустите

Нажмите **«Собрать»** (первая сборка Docker-образа занимает 5–10 минут).
Дождитесь статуса «Успешно развернуто».

## Шаг 5. Войдите в Telegram

1. Откройте вкладку **«Логи»** приложения. Там будет:

   ```
   [amvera] КЛЮЧ ДОСТУПА К СТРАНИЦЕ ВХОДА: AbCdEf123456
   [amvera] откройте: https://<домен-приложения>/?key=AbCdEf123456
   ```

2. Скопируйте ссылку, подставьте свой домен из Amvera и откройте её в
   браузере.
3. На странице появится QR-код. В Telegram: **Настройки → Устройства →
   Подключить устройство** (Link Desktop Device) → отсканируйте код.
4. Если у аккаунта включён облачный пароль (2FA), страница попросит его
   ввести — введите.
5. Через несколько секунд страница покажет «Юзербот работает», а в логах
   появится баннер Heroku и строка `🪐 Heroku 2.2.0 ... started`.

Сессия сохранена в `/data/sessions/heroku-<id>.session` — при перезапусках
и пересборках вход больше не нужен. Страница входа после этого закрыта:
она открывается только пока сессии нет.

## Что где лежит

```
/data                       ← постоянное хранилище Amvera
├── config.json             api_id / api_hash
├── sessions/               сессии Telegram (heroku-<id>.session)
└── loaded_modules/         модули, установленные через .dlmod

/app                        ← код из образа (не сохраняется между сборками)
└── heroku/                 исходники юзербота
```

Бэкап = скачать папку `Data` (вкладка «Репозиторий» → `Data`).
Файлы `config.json` и `*.session` — это доступ к аккаунту, никому их не
передавайте.

## Если что-то не работает

**Статус «Выполняется запуск» не меняется.**
Откройте логи. Если там ошибка порта — проверьте, что `containerPort: 8080`
совпадает с `APP_PORT`. Если пусто — подождите: первая сборка долгая.

**`EOFError` / `Enter phone:` в логах.**
Значит, приложение запускает `python -m heroku` напрямую, без
`supervisor.py`. Верните `CMD` из `deploy/amvera/Dockerfile` — именно он
поднимает страницу входа.

**«Не удалось войти» на странице.**
Контейнер не достучался до Telegram. Проверьте `api_id`/`api_hash`
(число и 32 символа) и что тариф Amvera не блокирует исходящие соединения к
`149.154.167.0/24`. Если Telegram недоступен из вашей страны — используйте
`--proxy-host/--proxy-port/--proxy-type/--proxy-secret`, добавив аргументы в
`BOT_CMD` внутри `supervisor.py`.

**«Нужен ключ доступа».**
Откройте адрес с `?key=…` из логов или задайте `AMVERA_LOGIN_TOKEN`.

**Сессия слетела (аккаунт разлогинили, Telegram отозвал сессию).**
Откройте страницу с ключом и нажмите «Сбросить сессии и войти заново»,
затем отсканируйте новый QR. Старые файлы уедут в
`/data/sessions-removed-<дата>`.

**Юзербот постоянно перезапускается.**
Смотрите причину в логах (`last_exit` тоже виден на странице). Чаще всего
это неверный `api_id`/`api_hash` или отозванная сессия.

**Нужен второй аккаунт.**
Этот supervisor рассчитан на один аккаунт. Второй добавляется уже из
Telegram командой `.addacc` (модуль HerokuAccounts), когда первый работает.

## Вариант без QR-кода: перенести готовую сессию

Если проще войти на своём компьютере, чем сканировать QR:

```bash
git clone https://github.com/Heroku-userbot/Heroku && cd Heroku
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python3 -m heroku            # пройти вход в терминале, дождаться баннера
```

Получится папка `sessions/` (файл `heroku-<id>.session`) и `config.json` в
корне проекта. Их нужно положить в постоянное хранилище Amvera:

1. Вкладка **«Репозиторий»** → выберите папку **`Data`**.
2. **«Загрузить данные»** → загрузите `config.json` и файл сессии.
   Файл сессии должен оказаться в `/data/sessions/`.
3. Перезапустите приложение — supervisor увидит сессию, сразу запустит
   юзербота и не будет показывать страницу входа.

`api_id`/`api_hash` при этом должны совпадать с теми, с которыми создавалась
сессия.

> Тот же трюк работает и локально через Docker: `docker compose run --rm
> worker` создаёт сессию внутри тома `worker`, откуда файлы достаются через
> `docker cp`.

## Ограничения

* **Одна реплика.** SQLite-сессии не любят несколько одновременных
  процессов: не включайте автомасштабирование.
* **Код живёт в образе.** Обновление = `git push` в репозиторий, к которому
  подключён проект (Amvera пересоберёт образ). Данные в `/data` при этом
  сохраняются.
* **Порт нужен только для статуса.** Юзербот работает через long polling,
  входящий HTTP не используется; страница на 8080 нужна Amvera для проверки
  живости и для входа.
