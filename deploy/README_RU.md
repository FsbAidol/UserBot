# Heroku Userbot на хостинге без терминала (Amvera, BotHost и подобные)

Amvera, BotHost и другие «app engine» не дают вводить команды: вместо
консоли — форма «главный файл / команда запуска», переменные окружения и
постоянный диск. Из-за этого обычная установка Heroku ломается дважды:

| Обычный VPS | PaaS без терминала |
|---|---|
| `python -m heroku` в консоли | команда запуска из `amvera.yml` / `CMD` / поля «Главный файл» |
| ввод API ID, телефона и кода в консоли | **некуда вводить** → `EOFError` |
| файлы в `~/.heroku` | постоянный диск: `/data` (Amvera) или `/app/data` (BotHost) |

Поэтому в репозитории появились три вещи, которые это закрывают:

| Файл | Зачем |
|---|---|
| `main.py` (в корне) | точка входа для PaaS: BotHost просит «главный файл», вот он |
| `deploy/paas/supervisor.py` | **замена консоли**: страница входа с QR-кодом, сохранение сессии на постоянный диск, запуск и перезапуск `python -m heroku --root` |
| `Dockerfile` (в корне) / `amvera.yml` | образ с ffmpeg, libmagic, git и node; порт и диск настроены |

Схема:

```
Telegram (сканируете QR на странице)
        │
        ▼
deploy/paas/supervisor.py ──► config.json  (api_id, api_hash)
        │                   └─► sessions/heroku-<id>.session
        │
        └──► python -m heroku --root  (сам юзербот, работает постоянно)
```

Порт нужен только для страницы входа и проверки живости: юзербот работает
через long polling, входящий HTTP ему не нужен.

---

## Что понадобится

1. `api_id` и `api_hash` с [my.telegram.org](https://my.telegram.org) →
   *API development tools*.
2. Тариф минимум **1 ГБ RAM** (на бесплатных 256 МБ юзербот убьёт OOM).
3. **Домен** приложения (на обоих хостингах есть бесплатный поддомен) —
   без него страница входа не откроется.

---

## Amvera

1. **Приложения → Создать приложение → GitHub** (или загрузите ZIP):
   подключите репозиторий, `amvera.yml` подхватится из корня.
2. Проверьте **«Конфигурацию»** — должно быть:

   ```yaml
   meta:
     environment: docker
     toolchain:
       name: docker
       version: latest
   build:
     dockerfile: Dockerfile
   run:
     persistenceMount: /data
     containerPort: 8080
   ```

3. **«Переменные»**: `api_id` и `api_hash` (именно строчными). Если на
   тарифе нет переменных — введите ключи прямо на странице входа, они
   сохранятся в `/data/config.json`.
4. Нажмите **«Собрать»** (первая сборка 5–10 минут).
5. Откройте **«Логи»**, найдите:

   ```
   [heroku-paas] КЛЮЧ ДОСТУПА К СТРАНИЦЕ ВХОДА: AbCdEf123456
   [heroku-paas] откройте: https://<домен-приложения>/?key=AbCdEf123456
   ```

6. Откройте ссылку → QR-код → **Telegram → Настройки → Устройства →
   Подключить устройство** → сканируйте. Если включён облачный пароль
   (2FA), страница его попросит.

Готово: в логах появится баннер `🪐 Heroku ... started`, страница покажет
«Юзербот работает».

## BotHost (bothost.ru)

> В BotHost действительно нет интерактивной консоли — их же документация
> советует userbot'ам String Session. Здесь то же самое, только вместо
> копирования строки сессии — QR-код на странице приложения.

1. **Создать бота**: платформа Telegram, язык **Python**, источник — Git
   (этот репозиторий и нужная ветка) или ZIP-архив.
2. **«Дополнительные настройки» → «Главный файл (точка входа)»: `main.py`**
   (не `heroku/main.py`! — это модуль пакета, отдельно он не запускается).
3. Там же включите **«Использовать домен»** и запомните порт (по умолчанию
   3000 или 8000). Приложение берёт порт из переменной `PORT`, поэтому
   менять код не нужно — главное, чтобы значение в панели совпадало.
4. **Переменные окружения**: `api_id`, `api_hash`. Если раздела нет
   (тариф Starter) — ключи вводятся на странице входа.
5. Задеплойте, откройте **логи** — там ключ и ссылка (см. пункт 5 раздела
   Amvera), затем откройте домен и сканируйте QR.
6. **Хотите модули с ffmpeg/libmagic/Pillow-фильтрами?** Включите
   **«Использовать собственный Dockerfile»** — в корне репозитория уже лежит
   готовый `Dockerfile` (ffmpeg, libmagic, git, nodejs). Без него
   используется автосборка из `requirements.txt`, и часть модулей будет
   ругаться на отсутствующий `ffmpeg`.

Данные на BotHost живут в **`/app/data`** (это постоянный диск, переживает
деплои), код — в `/app` (перезаписывается при каждом деплое). Supervisor
определяет папку данных сам: `/data` → `/app/data` → `./data`.

---

## Где что лежит

```
/data            (Amvera)  ┐
/app/data        (BotHost) ┘ постоянный диск
├── config.json             api_id / api_hash
├── sessions/               сессии Telegram (heroku-<id>.session)
└── loaded_modules/         модули, установленные через .dlmod
```

Бэкап = скачать эту папку в интерфейсе хостинга. `config.json` и
`*.session` — это доступ к аккаунту, никому их не передавайте.

## Вариант без QR: перенести готовую сессию

Если проще войти на своём компьютере, чем сканировать QR:

```bash
git clone https://github.com/Heroku-userbot/Heroku && cd Heroku
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python3 -m heroku            # войти в терминале, дождаться баннера
```

Получатся `sessions/heroku-<id>.session` и `config.json` в корне проекта.
Загрузите их в постоянную папку хостинга (Amvera: «Репозиторий» → `Data` →
«Загрузить данные»; BotHost: файловый менеджер / загрузка в `/app/data`),
файл сессии — в подпапку `sessions/`. Supervisor увидит сессию и сразу
запустит юзербота, не показывая страницу входа.

`api_id`/`api_hash` должны совпадать с теми, с которыми создавалась сессия.

## Если что-то не работает

**`EOFError` / `Enter phone:` в логах.**
Запускается `python -m heroku` напрямую, без supervisor. На BotHost это
значит, что в «Главном файле» указан `heroku/main.py` или `heroku` —
поставьте `main.py`.

**`ModuleNotFoundError: No module named 'heroku'` / `MODULE_NOT_FOUND`.**
Главный файл указан неверно или репозиторий во вложенной папке. Нужен
`main.py` из корня.

**`Cannot find module '/app/index.js'`.**
Хостинг принял проект за Node.js. Удалите `package.json`, если он есть, и
пересоздайте бота с языком Python.

**502 / 504 на домене.**
Порт в панели не совпадает с тем, что слушает приложение. Приложение берёт
`PORT` из окружения, поэтому достаточно указать в панели тот же порт, что
выбран в настройках домена, и передеплоить.

**«Нужен ключ доступа».**
Откройте адрес с `?key=…` из логов или задайте переменную `LOGIN_TOKEN`
(на Amvera также работает `AMVERA_LOGIN_TOKEN`).

**«Не удалось войти» на странице.**
Контейнер не достучался до Telegram: проверьте `api_id`/`api_hash`,
регион сервера и что хостинг не блокирует `149.154.167.0/24`. Если Telegram
недоступен из страны хостинга — добавьте в `BOT_CMD` внутри
`deploy/paas/supervisor.py` аргументы `--proxy-host`, `--proxy-port`,
`--type-proxy`, `--proxy-secret`.

**`Killed` / код 137 / OOM.**
Мало памяти. Юзерботу нужно ~300–500 МБ, берите тариф от 1 ГБ, Pro — 2 ГБ.

**Юзербот циклично перезапускается.**
Причина в логах (и в поле `last_exit` на странице). Чаще всего: неверные
`api_id`/`api_hash`, отозванная сессия или нехватка памяти.

**Сессию отозвали / аккаунт разлогинили.**
Откройте страницу с ключом и нажмите «Сбросить сессии и войти заново» —
старые файлы уедут в `sessions-removed-<дата>`, появится новый QR.

**Второй аккаунт.**
Supervisor рассчитан на один аккаунт. Второй добавляется из Telegram
командой `.addacc` (модуль HerokuAccounts), когда первый уже работает.

## Ограничения

* **Одна реплика.** SQLite-сессии не любят несколько процессов: не
  включайте автомасштабирование.
* **Код в образе / в /app.** Обновление = `git push` + новый деплой.
  Данные в `/data` (`/app/data`) сохраняются.
* **Первый вход требует домен.** Без домена страницу входа не открыть —
  тогда используйте вариант с переносом сессии.
